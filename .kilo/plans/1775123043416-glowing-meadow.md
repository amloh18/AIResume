# Resume Enhancer — Three-Layer Architecture & Feature Integration Plan

## Executive Summary

The resume enhancer needs a **fundamental architectural shift**. The current system conflates templates (structure), content (data), and presentation (styles) into a single monolithic rendering pipeline. Custom renderers hardcode both layout AND content rendering. Snippets are render variants, not content blocks. Switching templates loses user customizations.

This plan introduces a **three-layer architecture** — Template, Snippet, Style — connected by a **Binding System** that lets each layer evolve independently. Content becomes portable. Templates become slot blueprints. Styles become global design tokens. The CV becomes a living composition engine.

**Current Readiness: ~60%** | **Architecture Gap: Fundamental** | **Estimated Timeline: 10 weeks**

---

## Part 0: The Problem — Why Current Architecture Fails

### Current Flow (Broken Separation)
```
cvData (content) + ITemplate (structure+style) → CustomRenderer (hardcoded everything) → HTML
```

**Problems:**
1. Custom renderers (13 of them) hardcode section order, styling, AND content rendering
2. `UnifiedCVDataStructure` stores content as flat arrays (`work[]`, `education[]`, `skills[]`)
3. `SnippetOverrides` maps categories to render variant IDs — not content blocks
4. Template switch = re-render with different hardcoded component = user customizations lost
5. No content reusability — same bullet can't appear in multiple CVs
6. No edit history — no way to track snippet evolution

### Target Flow (Separated Layers)
```
Slot Bindings (which snippet goes where)
  + Template (slot blueprint + layout rules)
  + Snippet Library (atomic content blocks)
  + Style System (design tokens)
  → Composition Engine → HTML
```

## Part 1: Three-Layer Architecture Specification

### Layer 1: Template (Structure Blueprint)

A template defines **slots**, NOT content. It is a map of where things go.

```typescript
// src/types/template-v2.ts

interface TemplateV2 {
  id: string;
  name: string;
  description: string;
  thumbnail: string;
  category: 'professional' | 'creative' | 'minimal' | 'academic';
  tier: 'free' | 'premium';

  // Slot definitions — the core of the architecture
  slots: SlotDefinition[];

  // Layout configuration
  layout: {
    type: 'single-column' | 'two-column' | 'sidebar-left' | 'sidebar-right';
    columns: ColumnDefinition[];
  };

  // Style preset (can be overridden per-CV)
  stylePreset: StylePreset;

  // Page settings
  pageSettings: PageSettings;

  // Compatibility metadata
  version: number;
  compatibleSnippetTypes: SnippetType[];
}

interface SlotDefinition {
  id: string;                    // e.g., "header", "summary", "experience-1"
  type: SlotType;                // What kind of snippet can go here
  label: string;                 // Display name
  required: boolean;             // Must be filled
  repeatable: boolean;           // Can have multiple instances
  maxInstances?: number;         // Cap on repeats
  column: 'main' | 'sidebar';   // Which column
  order: number;                 // Position within column
  constraints: SlotConstraints;  // What snippet types are allowed
}

type SlotType =
  | 'header'           // Name, contact info
  | 'summary'          // Professional summary
  | 'experience'       // Work experience entry
  | 'education'        // Education entry
  | 'skills'           // Skills group
  | 'projects'         // Project entry
  | 'certifications'   // Certification entry
  | 'publications'     // Publication entry
  | 'languages'        // Language proficiency
  | 'awards'           // Award entry
  | 'volunteer'        // Volunteer experience
  | 'interests'        // Hobbies/interests
  | 'references'       // References
  | 'custom';          // User-defined

interface SlotConstraints {
  allowedSnippetTypes: SnippetType[];
  maxContentLength?: number;
  preferredFormat?: 'bullets' | 'paragraph' | 'tags' | 'grid';
}

interface ColumnDefinition {
  id: 'main' | 'sidebar';
  width: string;       // e.g., '70%', '30%'
  slots: string[];     // Ordered slot IDs
}
```

**Key principle:** A template is a **map of slots**. It never contains content.

### Layer 2: Snippet (Content Engine)

Snippets are **atomic, reusable content blocks** with lineage tracking.

```typescript
// src/types/snippet-v2.ts

interface SnippetV2 {
  id: string;                    // UUID
  type: SnippetType;             // What kind of snippet
  content: SnippetContent;       // The actual data
  metadata: SnippetMetadata;     // Dates, company, role, etc.
  formatHints: FormatHints;      // Intent formatting (not fixed styles)
  lineage: SnippetLineage;       // Parent tracking, edit history
  createdAt: Date;
  updatedAt: Date;
}

type SnippetType =
  | 'header'
  | 'summary'
  | 'experience'
  | 'education'
  | 'skills'
  | 'project'
  | 'certification'
  | 'publication'
  | 'language'
  | 'award'
  | 'volunteer'
  | 'interest'
  | 'reference';

// Content varies by type — discriminated union
type SnippetContent =
  | HeaderContent
  | SummaryContent
  | ExperienceContent
  | EducationContent
  | SkillsContent
  | ProjectContent
  | CertificationContent
  | PublicationContent
  | LanguageContent;

  phone: string;
  url: string;
  location: { city: string; region: string; countryCode: string };

}

interface EducationContent {
  institution: string;
  area: string;
  studyType: string;
  startDate: string;
  endDate: string;
  score?: string;
  url?: string;
  courses?: string[];
}

interface SkillsContent {
  category: string;
  skills: string[];
}

interface ProjectContent {
  name: string;
  description?: string;
  highlights: string[];
  keywords: string[];
  startDate?: string;
  endDate?: string;
  url?: string;
  current?: boolean;
}

interface CertificationContent {
  name: string;
  date: string;
  issuer: string;
  url?: string;
  description?: string;
}

interface PublicationContent {
  name: string;
  publisher: string;
  releaseDate: string;
  url?: string;
  summary?: string;
}

interface LanguageContent {
  language: string;
  fluency: string;
}

// Metadata for context-aware features
interface SnippetMetadata {
  industry?: string;
  role?: string;
  seniority?: 'junior' | 'mid' | 'senior' | 'lead' | 'executive';
  tags?: string[];              // User-defined tags
  source?: 'user' | 'library' | 'ai-generated' | 'imported';
  importSource?: 'linkedin' | 'pdf' | 'manual';
}

// Intent formatting — NOT fixed styles
interface FormatHints {
  emphasize?: string[];        // Words to emphasize (template decides how)
  metrics?: string[];          // Numbers/metrics to highlight
  keywords?: string[];         // ATS-relevant keywords
  hierarchy?: 'primary' | 'secondary' | 'tertiary';
}

// Lineage tracking
interface SnippetLineage {
  parentSnippetId?: string;    // Original snippet this was derived from
  derivedFrom?: string;        // CV instance this was cloned from
  editHistory: SnippetEdit[];  // Chronological edit log
  isGlobal: boolean;           // True if from shared snippet library
  libraryVersion?: number;     // Version in library (for updates)
}

interface SnippetEdit {
  timestamp: Date;
  field: string;               // Which field changed
  oldValue: string;
  newValue: string;
  source: 'user' | 'ai';
}
```

**Key rules:**
1. Snippets are **portable** across templates
2. Editing a snippet **creates a derived copy** (never mutates original)
3. Snippets store **format hints**, not fixed styles
4. Templates decide how to render format hints

### Layer 3: Style (Design System)

Styles are global and template-bound, NOT snippet-bound.

```typescript
// src/types/style-v2.ts

interface StylePreset {
  id: string;
  name: string;

  typography: TypographyScale;
  spacing: SpacingScale;
  colors: ColorPalette;
  layout: LayoutStyle;

interface TypographyScale {
  sectionHeading: TypeSpec;    // Section titles
  jobTitle: TypeSpec;          // Role/position names
  companyDate: TypeSpec;       // Company + date line

  headerPadding: string;       // Around header area
  ratio: number;               // sectionGap / itemGap (should be 2.0)

interface ColorPalette {
  primary: string;             // Main accent
  secondary: string;           // Secondary accent

}
```

### The Binding System (The Missing Link)

This is where everything connects.

```typescript
// src/types/binding.ts

interface CVInstance {
  id: string;
  userId: string;
  title: string;

  // The three layers
  templateId: string;          // Which template (slot blueprint)
  styleOverrides?: Partial<StylePreset>;  // Per-CV style tweaks

  // Slot bindings — maps template slots to snippets
  slotBindings: SlotBinding[];

  // Metadata
  status: 'draft' | 'published' | 'archived';
  version: number;
  cvType: 'master' | 'journey' | 'standalone';
  journeyId?: string;
  metadata: CVMetadata;
  createdAt: Date;
  updatedAt: Date;
}

interface SlotBinding {
  slotId: string;              // Template slot ID
  snippetId: string;           // Bound snippet ID
  order: number;               // Position (for repeatable slots)
  visible: boolean;            // Can be hidden without removing
}

// When user edits a snippet:
interface SnippetEditResult {
  originalSnippetId: string;   // What was bound
  newSnippetId: string;        // The derived copy
  slotId: string;              // Which slot to rebind
}
```

### The Reconciliation Engine

Handles template switching edge cases.

```typescript
// src/lib/reconciliation/reconciliation-engine.ts

interface ReconciliationResult {
  bindings: SlotBinding[];     // Updated bindings
  orphaned: string[];          // Snippets with no slot in new template
  empty: string[];             // Slots with no snippet in new template
  warnings: string[];          // Human-readable warnings
}

// Cases handled:
// 1. Slot exists in new template → Map existing snippet
// 2. Slot missing → Move snippet to fallback section or orphan pool
// 3. New slot introduced → Suggest snippet from library or leave empty
// 4. Slot type changed → Check compatibility, warn if mismatch
// 5. Repeatable slot count changed → Trim or pad with empties
```

## Part 5: Data Flow — How Everything Connects

### Creating a New CV
```
1. User selects template → TemplateV2 loaded
2. System creates CVInstance with empty SlotBinding[]
3. User adds snippets:
   a. Click "+" on Experience slot
   b. SnippetPickerV2 shows: user's snippets + library + AI suggestions
   c. User picks snippet → cloneSnippet() → bindSnippet()
4. Composition engine renders: bindings + snippets + template + style → HTML
5. User edits snippet → cloneSnippet() → rebind → updateSnippet()
6. User saves → CVInstance + SnippetV2[] persisted to MongoDB
```

### Switching Templates
```
1. User opens TemplateBrowserV2
2. Preview shows their snippets in new template layout
3. User clicks "Apply"
4. Reconciliation engine runs:
   a. Maps existing bindings to new template slots
   b. Identifies orphaned snippets
   c. Identifies empty required slots
5. TemplateSwitchDialog shows result
6. User confirms → CVInstance.templateId + slotBindings updated
7. Composition engine re-renders with new layout + same content
```

### Editing a Snippet
```
1. User clicks text in preview
2. System identifies slot + snippet under cursor
3. If snippet is shared/global → cloneSnippet() → rebind
4. Inline editor opens with snippet content
5. User edits → updateSnippet() logs edit to lineage
6. Composition engine re-renders affected slot
```

### AI Improving a Snippet
```
1. User selects text or clicks "Improve" on snippet
2. System sends: snippet content + slot constraints + role context to API
3. API returns improved text + format hints
4. cloneSnippet() → update content + formatHints → rebind
5. Format hints renderer applies visual treatment per style preset
```

```typescript
  const { state, dispatch } = useResumeEnhancer();
  const { cvData, selectedTemplate, surgeonAnalysis } = state;

    basics: cvData.personalInfo,
```

### Step 10.4: Path Translation Logic

**File:** `src/lib/utils/path-translation.ts`

```typescript
const PATH_MAPPING = {
  'experience': 'work',
  'role': 'title',
  'company': 'name',
  'description': 'highlights',
  'education': 'education',
  'institution': 'institution',
  'degree': 'studyType',
  'skills': 'skills',
  'category': 'name',
  'projects': 'projects',
  'certifications': 'certifications',
  'awards': 'awards',
  'languages': 'languages',
};

export function mapProPathToCVCircle(proPath: string): string {
  // 'experience.0.role' -> 'work.0.title'
  // Handle array indices and nested paths
  let result = proPath;
  for (const [pro, cv] of Object.entries(PATH_MAPPING)) {
    result = result.replace(new RegExp(`\\b${pro}\\b`, 'g'), cv);
  }
  return result;
}

export function mapCVCirclePathToPro(cvPath: string): string {
  // Reverse mapping
  let result = cvPath;
  for (const [cv, pro] of Object.entries(PATH_MAPPING)) {
    result = result.replace(new RegExp(`\\b${cv}\\b`, 'g'), pro);
  }
  return result;
}
```
